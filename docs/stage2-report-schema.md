# סכמת דוח Stage 2 (נכתב על ידי Claude, מאומת בקוד)

לכל מניה שעברה Stage 1 (US או IL) נכתב קובץ אחד בריפו הציבורי `portfolio-screener-data`:

```
data/reports/<YYYY-MM>/<TICKER>.json        # TICKER כמו ב-reportPath שבתור; BRK.B נכתב BRK-B
```

מה לכתוב ועל איזו מניה — `GET <web app /exec>?queue=1&token=<TICKERS_TOKEN>` מחזיר JSON עם מניות ה-PASS של החודש
(טיקר, שם, נתוני שלב 1, שווי שוק, מחיר ומטבע, קישור ל-filing, `reportPath`). דוגמה: `docs/examples/queue-response.json`.
הקוד (`finalizeMonth`, ימים 3/5/7) מושך את הקבצים, מאמת אותם, וכותב ל-`Stage2` ול-`History` (`stage2Report`).
אין בקבצים מפתחות; הם ציבוריים.

## השדות

| שדה | חובה | תוכן |
|---|---|---|
| `ticker` | כן | חייב להיות המניה של הקובץ |
| `month` | מומלץ | `YYYY-MM` של החודש; אם קיים חייב להתאים |
| `model` | כן | המודל שכתב (למשל `claude-opus-5-5`); נשמר כ-`model` ב-Stage2/History |
| `generatedAt` | כן | תאריך-שעה ISO; חייב להיות בחודש הדוח ולא בעתיד |
| `verdict` | כן | `continue` (חברה מעניינת) / `watch` (למעקב) / `reject` (לא עוברת) |
| `verdictReason` | כן | משפט-שניים של נימוק (עד ~40 מילה) |
| `business` | כן | תיאור עסקי: מה החברה עושה, איך מרוויחה, מקומה בשרשרת הערך, מה מונע מלקוחות לעבור למתחרים (עד ~70 מילה) |
| `segments[]` | כן (יכול להיות ריק) | 2–4 מגזרים: `{ name, share, trend, source }` — `share` למשל `"45% מההכנסות"` או `"לא נמצא מידע"` |
| `events[]` | כן (יכול להיות ריק) | שנה–שנתיים אחורה, בסדר כרונולוגי: `{ date, text, source }` — `date` בפורמט `YYYY-MM-DD` (או `YYYY-MM`) |
| `financials` | כן | ניתוח פיננסי קצר (עד ~110 מילה): צמיחה, רווחיות, מינוף; נתוני הסינון (ROE, D/E, FCF, P/E) כפי שהם, מספרים חשובים ב-`**bold**` |
| `risks[]` | כן (יכול להיות ריק) | סעיף נפרד: `{ text, source }` (תחרות, מינוף, תלות בלקוח/אירוע, סחורות/מט"ח, מורכבות) |
| `thesis` | כן | תזה ופוטנציאל ל-2–3 שנים (עד ~60 מילה) |
| `sources[]` | כן | `{ id, title, url, label?, kind?, date? }` — ראו למטה |

`header` (שם, טיקר/מספר נייר, שווי שוק, מחיר ומטבע) **לא** נכתב בקובץ: הקוד בונה אותו מהנתונים שלו.
היקף כולל: כ-400–700 מילה. כתיבה בעברית, אנליטית-שיחתית, בלי שיווקיות; גוף ראשון במשורה.
`source` בפריט (מגזר/אירוע/סיכון) הוא מזהה אחד (`"S2"`) או רשימה (`"sourceIds": ["S2","S3"]`).

## כללי המקורות (נאכפים בקוד, לא רק מומלצים)

1. כל טענה עובדתית — מספר, אחוז, אירוע, תאריך, חוזה — מלווה בתג `[S#]` בסוף המשפט, ו-`S#` קיים ב-`sources[]`.
2. `sources[]`: לכל מקור `id` (`S1`, `S2`…), `title` (שם המסמך ותאריכו) ו-`url` (http/https כשקיים).
   `label` הוא התווית הקצרה שמוצגת אחרי הטענה (`"10-K 04/02/2026"`); בלעדיו נגזרת מה-`title`.
   מקור לדוגמה של נתוני שלב 1: `{ "id": "S1", "title": "נתוני הסינון הכמותי (Stage 1) של X", "label": "נתוני Stage 1" }` (בלי URL).
   לחברה ישראלית (חבילה עם `market: "IL"`): כל מקור (חוץ מ-S1) חייב `url` https ב-`maya.tase.co.il` / `tase.co.il` או ב-`bizportal.co.il` (`CONFIG.IL_REPORT_SOURCE_HOSTS`), אחרת הקובץ נדחה. MAYA לא נקראת בקוד, ולכן מספר שמצוטט ממנה "לא ניתן לאימות" (לא נמחק); עמודי Bizportal נקראים חי. החבילה מכילה בלוק `il` (נתוני IL_Data הגולמיים באלפי ש"ח) — מספרים ממנו נבדקים אוטומטית מול S1. אין Gemini לישראליות.
3. מגזר או אירוע בלי מקור מוכר — **נמחק**. תאריך אירוע שאינו תאריך אמיתי — האירוע נמחק.
   אירוע שמצטט מקור `kind: "news"` עם `date` מקבל את תאריך המקור.
4. טענה בלי מקור אינה עובדה: כתוב אותה כהערכה והוסף `(הערכה)` בסופה. משפט בלי תג מקור ובלי `(הערכה)` יסומן אוטומטית `(הערכה)`.
   סיכון בלי `source` נשמר ומסומן `(הערכה)`; סיכון שמצטט מקור שלא קיים — נמחק.
5. אין מידע — כתוב `לא נמצא מידע`. אין להמציא נתונים.
6. אסור להעתיק טקסט (גם לא בניסוח קרוב) מאתרי סקירה או מכתבות; מותר להשתמש בשמות בלבד.
7. תגי `[S#]` שאינם ב-`sources[]` מוסרים מהטקסט (ונספרים כהסרה). אם יותר ממחצית הפריטים נמחקו הסקירה נשמרת כ-`low-confidence`.

## אימות אוטומטי של הקוד (חדש)

אחרי האימות הקיים הקוד בודק את הדוח מול המקורות שהוא יכול לקרוא (`Verify.gs`), ושומר את התוצאה בדוח (`verification`) ומציג אותה בכרטיס:

1. **מספרים:** כל מספר במשפט שמצטט מקור נבדק מול המקור: *נמצא* (אותן ספרות), *בקירוב* (אחרי שינוי סדר גודל, למשל 4.18 מיליארד מול 4,184 מיליון), *לא נמצא* (כל המקורות שצוטטו נקראו והמספר אינו באף אחד — מספר מחושב, כמו 100%-56%, יסומן כך; ציין זאת בטקסט), *לא ניתן לאימות* (מקור שהקוד לא יכול לקרוא). שלושה מספרים או יותר שלא נמצאו — הסקירה נשמרת כ-`low-confidence`.
2. **ציטוט (אופציונלי, מומלץ):** בפריט של `segments[]` / `events[]` אפשר להוסיף `"quote"` — ציטוט קצר (עד 25 מילה) מהמקור, מילה במילה. אם המקור קריא והציטוט אינו בו — הפריט נמחק.
3. **קישורים:** מקור שמחזיר 404/410 נחשב מת: פריט שצוטט רק ממנו נמחק והסקירה נשמרת כ-`low-confidence`. 403 נחשב "חסום" (לא נבדק).
4. **שלב 1 מול הדוחות:** אם קיים `data/facts/<TICKER>.json`, הקוד מחשב ממנו FCF yield / ROE / P/E / חוב להון ומציג פער גדול מול נתוני שלב 1.

מה הקוד קורא: נתוני שלב 1 (מקור `kind: "metrics"`), טקסט ה-10-K/20-F שבגשר (כשה-`url` של המקור הוא ה-`filing.sourceUrl` של חבילת הקלט), קובצי `data/releases/<TICKER>.json` (הודעות תוצאות 8-K ex.99 — מזוהות לפי מספר ה-accession ב-URL), `data/facts/<TICKER>.json` (מקור `kind: "facts"` עם ה-`url` של הקובץ) וכל עמוד שאינו ב-sec.gov (נקרא חי). מסמכי sec.gov אחרים אינם קריאים לקוד ולכן "לא ניתנים לאימות" — העדף מקורות שהגשר מחזיק.

**מקורות מומלצים לנתונים פיננסיים:** `data/facts/<TICKER>.json` (עד 6 שנות הכנסות, רווח, תזרים, חוב, הון ומרווחים, מחושבים מ-XBRL; ציין אותו כמקור `facts`), והודעת התוצאות האחרונה מ-`data/releases/<TICKER>.json`. מספר שנלקח מהם נבדק אוטומטית.

## מה גורם לדחיית הקובץ כולו (המניה נשארת "ממתין לניתוח עומק")

`ticker` שגוי · `month` לא מתאים · חסר `model` · `generatedAt` חסר/בעתיד/מחוץ לחודש · `sources[]` ריק או כפילות מזהים ·
`verdict` לא חוקי · `verdictReason` ריק · JSON שאינו אובייקט. הסיבה נרשמת ב-RunLog וב-`Stage2_Queue.note`.

## דוגמה

הקובץ המלא (חברה בדויה `EXMP`): [`examples/report-EXMP.json`](examples/report-EXMP.json).

```json
{
  "ticker": "EXMP", "month": "2026-10", "model": "claude-example-model", "generatedAt": "2026-10-02T09:30:00Z",
  "verdict": "watch",
  "verdictReason": "מדדים כמותיים טובים, אבל הרווח תלוי בחוזה אחד גדול. כדאי לעקוב אחרי המשך החוזה [S3].",
  "business": "EXAMPLE Aerospace מייצרת רכיבי מנועים לחברות תעופה וביטחון [S2]. …",
  "segments": [{ "name": "Engine Components", "share": "60% מההכנסות", "trend": "צמיחה מתונה", "source": "S2" }],
  "events": [{ "date": "2026-09-21", "text": "נחתם חוזה אספקה רב-שנתי חדש", "source": "S3" }],
  "financials": "ה-ROE עומד על **25.0%** … [S1]. נראה שהמינוף נמוך יחסית לתחום (הערכה).",
  "risks": [{ "text": "תלות בלקוח ביטחוני אחד מרכזי [S2]", "source": "S2" }, { "text": "חשיפה לחומרי גלם (הערכה)" }],
  "thesis": "אם החוזה יתממש במלואו, יש פוטנציאל לצמיחה ברווחיות [S3].",
  "sources": [
    { "id": "S1", "title": "נתוני הסינון הכמותי (Stage 1) של EXMP", "label": "נתוני Stage 1" },
    { "id": "S2", "title": "EXMP 10-K (04/02/2026)", "label": "10-K 04/02/2026", "url": "https://example.com/filings/exmp-10k-2026.htm" },
    { "id": "S3", "title": "Example Wire, 21/09/2026: EXMP signs contract", "label": "Example Wire 21/09/2026", "kind": "news", "date": "2026-09-21", "url": "https://example.com/news/exmp-contract" }
  ]
}
```

הערה: הדוגמה בדויה ונועדה להמחשת הפורמט בלבד. `model` ו-`generatedAt` הם השדות שנוספו לסכמה הקודמת.
